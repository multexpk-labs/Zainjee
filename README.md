## About

My engineering journey started around **2011**, when I was an Engineering Fundamental student.

At that time, I was learning by experimenting directly with computers, operating systems, software and security tools rather than relying on today's AI-assisted development environment.

I started with **BackTrack 3 R5** and later **Kali Linux**, exploring security tools, code analysis, reverse engineering, decoding/deobfuscation techniques, and understanding how software behaved internally.

That early experimentation gradually changed direction:

> **Instead of only using tools to break or decode software, I wanted to understand how the software itself was made.**

That became the foundation for learning programming, operating systems, web technologies, databases, networking, automation and software architecture.

# Learning Philosophy

I did not follow one single curriculum.

My learning path was a combination of:

**experimentation + documentation + courses + real projects + troubleshooting**

I learned from hands-on Linux experimentation, programming projects, Laracasts, Udemy, Google learning resources, edX, Kaggle, Google Colab, official documentation, open-source projects, production problems and debugging real systems.

# From Tools to Building Systems

One of the most important changes in my journey was moving from **using existing tools**, to **understanding how the tools work**, and eventually to **building the systems myself**.

That progression shaped the way I approach engineering today.

I try to understand the complete chain:

**Operating System → Network → Server → Runtime → Application → Database → API → Automation → User**

And now increasingly:

**GPU → Model → Inference → API → Agent → Automation → Application → Infrastructure**

# Research & Engineering Principles

- Build before assuming.
- Test on real systems.
- Read documentation.
- Understand the underlying technology.
- Automate repetitive work.
- Keep production and research environments separated.
- Document failures as well as successes.
- Never publish credentials or private customer information.
- Prefer reproducible experiments.
- Share useful knowledge where it can help others.
